# Winny トラフィックパターン可視化ツール

P2P ネットワークへの参加・検索・キャッシュ転送・Port0 の仲介の流れを、ブラウザの中で描く模擬です。

## これは何で、何でないか

- 合成データだけで動きます。実ネットワークには接続しません。ノード・所在・ファイル名はすべて架空です。
- Winny 本体でも、Winny と通信できる互換クライアントでもありません。通信の枠や暗号は実装していません。
- Winny の開発者・権利者とは無関係です。Winny の利用を勧めるものでもありません。
- `public/index.html` 1 枚で完結します。外部のスクリプトやフォントは読み込みません。

## 解析にもとづく所と、本ツールが決めた所

静的解析で読んだ手順をもとにした動き：

- 保存してあるノードへ接続し、紹介で候補を増やす（解析した参加の経路には、中央の登録サーバは見当たらなかった）
- クエリが隣のノードへ広がる。受けたノードが、手持ちのキーを足して送り返す（道筋の細部は未確認）
- 所在が Port0 のときは、両方とつながっている仲介ノードが知らせを出し、Port0 の側から外向きに接続する
- 要求元も所在も Port0 のときは、直接つなぐ条件を満たさない。その先の受け渡しは解析で確かめていないので、描かずに止める

見せるために本ツールが決めた所（解析で確かめた値ではありません）：

- NAT の内側のノードを全部 Port0 として描く（解析では、NAT 配下かどうかと Port0 の申告は別の判定）
- NAT の内側の割合（初期値 8 割）、線の張り方、クエリを広げる台数（6 台）と段数（3 段）
- 転送の玉を 8 個連ねること、ファイルの種類と最初の手持ち、解説デモの筋書き
- 回線速度による上流・下流の分かれ方は入れていない

## 置き方（Cloudflare）

Workers（静的アセット）の場合：

- ビルドコマンド: なし（空欄）
- デプロイコマンド: `npx wrangler deploy`
- 本番以外のブランチのデプロイコマンド: `npx wrangler versions upload`
- ルートディレクトリ: `/`
- Worker の名前は `wrangler.jsonc` の `name` と同じにする

Pages の場合：

- ビルドコマンド: なし（空欄）
- 出力ディレクトリ: `public`

`public/_headers` で、外部への読み込みと送信を禁止する CSP を付けています。

## 操作

- 解説デモ: 参加 → 検索 → 所在（キー）→ 転送 → Port0 の仲介 を順に、説明つきで見せる
- 再生／停止: 自由に動かす。「並列度」で同時に走る量を、「速さ」（10 倍まで）で進み方を変える
- ノード数（8〜2000）、NAT の内側の割合（0〜98%）
- 図の左上: ネットワーク図／シーケンス図の切り替え、回転を止める。図はドラッグで回せる
